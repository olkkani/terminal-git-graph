# terminal-git-graph — 시각 개선 설계 (보강)

작성일: 2026-11-04 · 상태: 초안(사용자 승인 대기) · 기반: `2026-11-03-terminal-git-graph-design.md`

## 1. 의도

MVP(원본 기능 전부)는 끝났다. 하지만 화면이 "글자로 그린 도구" 느낌이라, 참고 화면(원본 herdr-git-graph 스크린샷)처럼 **배지는 둥근 알약, 그래프는 부드러운 곡선, 헤더·상세는 GUI 클라이언트 같은 인상**을 주고 싶다. 목표는 정보량과 가독성을 GUI Git 클라이언트 수준으로 올리는 것이다.

참고 화면은 파일 `reference-git-graph.png`로 작업 폴더에 있다. 이것은 원본 프로젝트의 스크린샷이므로 **저장소에 커밋하지 않고**, 문서나 README에도 넣지 않는다(기존 제약: 원본 `preview.png` 사용 금지).

## 2. 실험 결과 (사실)

2026-11-04에 사용자가 직접 실행한 버려진 스파이크(안티앨리어싱된 둥근 알약과 곡선 이미지를 Kitty graphics 프로토콜로 전송)에서 **ghostty 일반 창과 herdr 분할 창 모두에서 이미지가 정상 표시**됐다. 따라서 그래픽 렌더링은 이 두 환경에서 가능하다. tmux/zellij 등 다른 환경은 확인하지 않았다.

## 3. 목표 / 비목표 / 안티골

### 목표
- **글자 모드(기본 화면, 모든 터미널)**: 알약형 배지, 종류별 아이콘, 부드러운 노드/곡선, 칼럼 헤더 행, 분절형 필터 컨트롤, 정돈된 상세 패널로 참고 화면에 가깝게 만든다.
- **그래픽 모드(선택, 지원 터미널)**: 그래프 레인(곡선, 노드, HEAD 링, 점선)을 **실제 이미지**로 그려 안티앨리어싱된 곡선을 보여 준다. 시작 시 자동 감지하고, 실패하면 글자 모드로 돌아간다.
- 설정 `renderer = "auto" | "text" | "graphics"`(기본 `auto`)로 직접 선택할 수 있다.

### 비목표
- 배지/제목/날짜 등 **텍스트를 이미지로 그리지 않는다**(폰트 래스터화 없음). 글자는 항상 터미널이 그린다.
- 배지 알약 배경을 이미지로 그리는 것(z-index 레이어링)은 이번 범위 밖이다. 확인된 실험 범위(이미지 표시)를 넘는다.
- 터미널 멀티플렉서(tmux, zellij) 패스스루 지원. 감지에 실패하면 글자 모드다.
- Sixel, iTerm2 프로토콜 지원.
- 새 기능이나 새 Git 동작 추가.

### 안티골
- 그래픽을 지원하지 않는 터미널에서 깨진 문자열, 빈 그래프, 입력 지연이 생기는 경우.
- 그래픽 모드가 글자 모드보다 느리게 느껴지는 경우(스크롤 끊김, 깜빡임).
- 메뉴/대화상자가 열렸는데 그 위로 이미지가 비쳐 보이는 경우.
- 종료 후 터미널에 이미지가 남는 경우.

## 4. 제약

- 기존 제약 유지: MIT, 코드 직접 작성, 의존성은 MIT/Apache/BSD/ISC(+ 기존에 허용한 Unicode-3.0, Zlib, CC0-1.0), 셸 없는 git 호출 등.
- **기존 "특정 터미널 전용 프로토콜 금지"를 다음으로 바꾼다**: 터미널 전용 기능은 **감지에 성공했을 때만 선택적으로** 쓰고, 항상 글자 모드로 완전히 동작해야 한다. 글자 모드는 모든 기능을 갖춘다.
- 이미지 전송은 Kitty graphics 프로토콜(`ESC _ G … ESC \`)만 쓴다.
- Nerd Font는 선택이다. 설정 `nerd_font = true`일 때만 전용 글리프(알약 끝 모양, 브랜치/클라우드/태그 아이콘)를 쓰고, 기본값은 `false`다(폰트는 감지할 수 없다). `false`면 일반 유니코드와 ASCII로 대체한다.
- 그래픽 모드의 첫 프레임 지연과 스크롤 성능은 글자 모드와 비슷해야 한다(§7).

## 5. 요구사항

### 5.1 글자 모드 개선
- **배지**: 체크아웃한 로컬 브랜치는 채운 알약(강조색 배경, ✓), 다른 로컬 브랜치는 연한 배경, 원격 브랜치와 태그는 색 글자의 윤곽 느낌(어두운 틴트 배경). 종류별 아이콘(로컬 브랜치, 원격, 태그). `nerd_font`면 둥근 끝 글리프 사용. 아이콘은 모두 표시 폭 1칸이어야 한다.
- **그래프**: 노드를 `●`/`◯` 대신 더 부드러운 기호로(빌더 재량이되 폭 1칸), 곡선은 둥근 박스 문자 유지. 병합 행은 흐리게(기존).
- **칼럼 헤더 행**: `Graph  Description  Date  Author  Commit`을 흐리게 표시한다(표시되는 열만).
- **헤더**: 브랜치 알약, 분절형 `All branches | Current` 컨트롤, 체크박스형 Remotes(`☑`/`☐`), 우측에 커밋 수와 Fetch. 폭이 좁으면 기존처럼 항목을 줄인다.
- **상세 패널**: 라벨 열(`Commit`, `Parents`, `Author`, `Date`)은 흐리게, 해시는 강조색, 파일 상태 글자(A/M/D)는 색, `+N`은 초록, `-N`은 빨강. 제목은 굵게.
- 선택한 행은 행 전체 폭에 배경을 깐다(기존 유지).

### 5.2 그래픽 모드
- **대상**: 그래프 열만 이미지로 그린다. 레인의 선과 곡선(분기/병합), 노드(원), HEAD 링, 병합 행의 흐림, Uncommitted 행의 점선 연결.
- **감지(auto)**: 시작 시 Kitty graphics 질의에 응답이 오고, 셀 픽셀 크기를 알 수 있을 때만 켠다. 응답 대기는 최대 300ms이며, 입력 버퍼에 남는 바이트가 없어야 한다. 환경 변수 힌트(`TERM_PROGRAM`, `TERM`, tmux 여부 등)는 보조로만 쓴다(힌트만으로 켜지 않는다). `renderer = "graphics"`로 강제했는데 감지에 실패하면 시작 후 한 번 안내 대화상자를 보여 주고 글자 모드로 간다.
- **전송 방식**: 행 단위 이미지를 한 번 전송해 두고(키: 행 내용과 셀 크기와 색 팔레트의 해시), 프레임마다 배치(placement)만 한다. 화면이 바뀌면 이전 배치를 지우고 보이는 행만 다시 배치한다. 같은 내용은 재전송하지 않는다.
- **겹침 규칙**: 메뉴, 대화상자, "Terminal too small" 화면이 떠 있는 동안은 이미지 배치를 모두 지우고 그래프 열을 글자 모드로 그린다(이미지가 위에 비쳐 보이지 않게).
- **리사이즈/글꼴 크기 변경**: 셀 픽셀 크기가 바뀌면 캐시를 비우고 다시 그린다. 크기를 알 수 없게 되면 글자 모드로 돌아간다.
- **종료/패닉**: 모든 이미지와 배치를 삭제하고 터미널을 복원한다.
- **오류**: 이미지 쓰기가 실패하면 글자 모드로 전환하고 계속 동작한다(앱 종료 금지).

## 6. 빌더 재량
- 알약/아이콘/노드에 쓰는 구체적 글리프, 색조 값, 곡선 수식(베지어 제어점), 선 굵기, 안티앨리어싱 방식.
- 감지 시 질의 응답을 읽는 방법(스레드, 비차단 읽기 등).
- 캐시 크기와 해시 방식.
- 그래픽 모드의 구성 요소 분리(`gfx` 모듈 구조).

## 6.1 검토 질문에 대한 결정 (**제 판단**, 확인 필요)
- **참고 이미지 위치**: `/Users/jin/Documents/repository/terminal-git-graph/develop/reference-git-graph.png`(develop worktree의 untracked 파일). 시각적 목표로만 쓰고 커밋하지 않는다. 읽을 수 없으면 §5.1의 글이 수용 기준의 전부다.
- **이미지 포맷**: 원시 RGBA(`f=32`)를 쓴다. 래스터라이저는 직접 작성하고 새 래스터 크레이트는 쓰지 않는다. 행 이미지 캐시로 전송량을 줄이고, 성능 테스트가 기준을 못 맞출 때만 zlib 압축(`o=z`, `flate2` MIT/Apache)을 추가한다.
- **감지 방식**: 이벤트 루프가 시작되기 전에 `/dev/tty`를 raw로 읽어 질의에 응답한다(Kitty 질의 + 셀 크기 질의 `CSI 16 t` + 마지막에 `CSI c`로 응답 끝 표시, 총 300ms 이내). `libc`(MIT/Apache, unix 전용)를 의존성으로 추가한다. Windows는 이미 비목표다. 이 단계는 단위 테스트로는 바이트 파서만 검증한다.
- **셀 픽셀 크기**: 감지 때 `CSI 16 t` 응답을 우선하고, 없으면 crossterm `window_size()`의 픽셀 필드에서 계산한다. 둘 다 없으면 글자 모드다. 실행 중 리사이즈에서는 `window_size()`로 다시 계산하고, 픽셀 값이 0이면 시작 때 얻은 셀 크기를 유지한다. 글꼴 크기 변경은 `window_size()`가 갱신될 때만 반영된다.
- **정리 규칙**: 화면 전환, 메뉴/대화상자, "Terminal too small" 어느 경우든 같은 훅 하나(이벤트 루프의 프레임 직후)에서 "이미지 배치 모두 삭제 + 글자 모드로 그래프 열 그리기"를 수행한다. 프레임마다 보이는 행의 배치를 다시 만든다.
- **이미지 투명도**: 행 이미지는 배경이 투명하다. 선택/호버 배경은 ratatui가 그린 셀 배경이 비쳐 보이게 한다. 캐시 키에는 선택 상태를 넣지 않고, 행 내용(레인 구조, 색, 병합 흐림)과 셀 크기를 넣는다.
- **설정**: `renderer`와 `nerd_font`는 기존 `config.toml`에 둔다. 잘못된 `renderer` 값은 경고 대화상자와 `auto`로 처리한다. CLI 플래그는 추가하지 않는다.
- **글리프 폭**: 새로 쓰는 글리프는 `unicode-width`의 `width()`와 `width_cjk()`가 모두 1이어야 하며, 이를 테스트로 확인한다. 기존의 `●`, `◯`, `✓`는 유지한다(모호한 폭이지만 이미 사용 중이고, 그래픽 모드에서는 노드가 이미지로 대체된다).

## 7. 성공 기준
- 글자 모드 화면이 참고 화면의 구성(알약 배지, 헤더 컨트롤, 칼럼 헤더, 상세 정렬)을 갖춘다.
- ghostty와 herdr 분할 창에서 `renderer = "auto"`로 그래픽 모드가 켜지고, 곡선이 부드럽게 보인다.
- 미지원 환경(예: `TERM=dumb`, `renderer = "text"`)에서는 기존과 같이 완전히 동작한다.
- 그래픽 모드에서 스크롤 중 프레임당 이미지 전송은 새로 보이는 행에 한정되고, 입력 반응이 글자 모드와 체감 차이가 없다.
- 메뉴/대화상자 위에 이미지가 비치지 않고, 종료 후 터미널에 이미지가 남지 않는다.
- 자동 테스트: 프로토콜 바이트 출력, 래스터 픽셀, 감지 파서, 설정 파싱, 글자 모드 렌더(버퍼 단위)가 통과한다. 실제 터미널 확인(ghostty, herdr)은 사용자가 직접 한다.
