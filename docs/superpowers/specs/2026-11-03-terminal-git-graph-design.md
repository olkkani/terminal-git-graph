# terminal-git-graph — 설계 문서

작성일: 2026-11-03 · 상태: 검토 완료, 사용자 최종 승인 대기

## 1. 의도와 배경

`git log --graph`는 설치 없이 쓸 수 있지만 정보량과 가독성이 부족하다. GUI Git 클라이언트(VS Code Git Graph 등)처럼 색 레인 그래프, 브랜치/태그 라벨, 커밋 상세, 변경 파일, Git 동작을 한 화면에서 보고 싶다.

참고 프로젝트 [rabeeh-ta/herdr-git-graph](https://github.com/rabeeh-ta/herdr-git-graph)(MIT)가 이를 잘 구현했지만 **Herdr 데스크톱 앱에서만** 동작한다. 이 프로젝트는 같은 기능을 **어떤 터미널에서든** 쓸 수 있는 TUI로 만든다. 주 사용 형태는 터미널 옆 사이드 패널(분할 창)이다.

## 2. 목표 / 비목표 / 안티골

### 목표
- 원본 herdr-git-graph의 기능을 모두 구현한다(§4).
- git GUI 수준의 정보 밀도와 디자인(색 레인, 배지, 상세 패널)을 터미널에서 낸다.
- 좁은 사이드 패널(약 40~60칸)에서 우선 잘 동작하고, 넓으면 컬럼을 더 보여 준다.
- 설치가 간단하다(단일 실행 파일, 런타임 의존성 없음).

### 비목표
- Herdr 전용 기능: Changes 패널 연동, 에이전트/터미널 탭 열기, 상단바 버튼, 업데이트 알림.
- Windows 지원(macOS 우선, Linux는 가능하면 지원).
- 원본도 지원하지 않는 기능(Ctrl+F 검색, 브랜치 드롭다운, 그래프 내 pull, interactive rebase, 상세의 파일별 동작)은 1차 범위 밖이다. 이후 추가할 수 있다.

### 안티골 (기술적으로 동작해도 실패)
- 느려서 상시 띄워 둘 수 없는 경우(시작 지연, 스크롤 끊김, 높은 CPU).
- 사용자가 확인하지 않은 상태에서 저장소를 변경하는 경우.
- 일부 터미널에서만 깨지거나 동작하는 경우(특정 터미널 전용 기능 의존).
- 원본 코드를 복사해 라이선스 의무를 어기는 경우.

## 3. 제약

- **라이선스**: 프로젝트는 MIT. 코드는 직접 작성하고 원본 소스를 복사/번역하지 않는다. 복사가 불가피하면 해당 부분에 MIT 저작권 표기를 남긴다. 의존성은 MIT/Apache-2.0/BSD/ISC만 허용(GPL 계열 금지).
- **이름/상표**: 프로젝트명 `terminal-git-graph`. "Herdr", "Git Graph"를 이름이나 로고에 쓰지 않는다. README에 "영감을 받음"으로 출처를 밝힌다. 원본 `preview.png`는 쓰지 않고 자체 스크린샷을 만든다.
- **환경**: ghostty와 herdr(분할 창)에서 동작해야 한다. 마우스 보고, 트루컬러, 유니코드를 전제로 하되, 특정 터미널 전용 프로토콜에 의존하지 않는다. Nerd Font 글리프는 선택이며 없으면 일반 유니코드로 대체한다.
- **git 호출**: 시스템 `git` CLI를 셸 없이 인자 목록으로 호출한다. 사용자가 입력한 이름은 `-`로 시작할 수 없다.
- **네트워크**: git이 네트워크에 접근하는 것은 Fetch, Fetch all, Pull, Push, 원격 브랜치 삭제를 명시적으로 실행할 때만이다. 프로그램 자체의 텔레메트리/업데이트 확인은 없다.

## 4. 기능 범위 (원본 기능 전부)

### 4.1 그래프 보기
- 최신순 표. 컬럼: 그래프, 설명, 날짜(상대 시간), 작성자, 커밋 해시. 폭이 좁으면 그래프+설명+날짜 위주로 줄이고, 넓으면 작성자와 해시를 추가한다.
- 브랜치마다 색 레인, 분기/병합 지점은 곡선(유니코드 박스 문자)으로 그린다. 병합 커밋은 흐리게 표시한다.
- 체크아웃한 브랜치 라벨에 ✓, 헤더에 현재 브랜치 표시, HEAD 행은 링 모양과 색조로 강조한다.
- 라벨: 로컬 브랜치(원격 추적이면 `main | origin`), 원격 전용 브랜치, 태그. 한 행에 라벨이 많으면 잘린다.
- 최상단에 "Uncommitted changes (N)" 행을 두고 HEAD와 점선으로 잇는다.
- 툴바/필터: All branches ↔ Current 전환, Remotes 표시 토글, 커밋 수 표시, Fetch.
- 처음 300개를 읽고, 끝까지 스크롤하면 300개씩 추가로 읽는다.

### 4.2 커밋 상세
- 커밋 선택 시 하단(또는 폭이 좁으면 전환되는 화면)에 메시지, 전체 해시, 부모, 작성자, 날짜, 변경 파일 목록과 +/- 통계를 보여 준다.
- 파일을 선택하면 그 파일의 diff를 본다. untracked 파일은 내용을 보여 준다.

### 4.3 실시간 갱신
- ref 변경(commit, checkout, fetch를 다른 터미널에서 해도)을 감지해 자동 리로드한다.
- 작업 트리 편집에 따라 Uncommitted 행을 갱신한다.
- 본 저장소와 열어 본 커밋은 캐시해 재방문 시 즉시 표시한다.

### 4.4 Git 동작 (모두 확인 대화상자를 거침)
브랜치 체크아웃(더블클릭/Enter)과 Fetch만 확인 없이 실행한다. 위험한 선택은 빨간색으로 표시하고, git이 거부하면 git의 메시지를 그대로 대화상자에 보여 준다.

- **로컬 브랜치**: 체크아웃, 이름 변경, 삭제, 현재 브랜치로 merge, 현재 브랜치를 그 위로 rebase, push, 이름 복사.
- **원격 브랜치**: 체크아웃(로컬이 없으면 로컬 이름을 먼저 물음), merge, 원격에서 삭제, 이름 복사.
- **태그**: 삭제, push, 이름 복사.
- **커밋**: 태그 추가, 브랜치 생성, 체크아웃, cherry-pick, revert, merge, rebase, reset(soft/mixed/hard), 해시/제목 복사.
- **Uncommitted changes**: commit(전체를 스테이징 후, 또는 스테이징된 것만), stash, reset.

### 4.5 여러 저장소 (Manygit)
- 저장소가 아닌 폴더에서 실행하면 하위 저장소를 폴더별로 묶어 목록으로 보여 준다. 탐색 깊이는 기본 3단계(설정 1~5), 숨김 폴더와 `node_modules`류 폴더는 건너뛰고, 홈 폴더나 그 상위는 스캔하지 않는다.
- 저장소마다 브랜치, 미커밋 변경, upstream 대비 ahead(↑)/behind(↓), 미푸시, 원격 없음을 표시한다. 목록이 보이는 동안 15초마다 상태를 갱신한다. 선택적으로 각 저장소의 최신 태그를 보여 준다.
- 저장소를 선택하면 그 그래프로 들어가고, 헤더 이름에서 다른 저장소로 전환하거나 목록으로 돌아간다.
- 저장소 메뉴: pull/push/fetch(↑/↓가 요구하는 것부터), commit, stash, reset, 원격 페이지 열기, 경로 복사. Fetch all(원격 있는 모든 저장소, 로그인 프롬프트 끔).

### 4.6 입력 방식
- 키보드와 마우스를 모두 지원한다. 마우스: 클릭 선택, 더블클릭 체크아웃, 우클릭 컨텍스트 메뉴, 스크롤. 키보드로도 모든 동작에 접근할 수 있어야 한다(키 매핑은 빌더가 정한다, §6).
- 우클릭 메뉴에 대응하는 키보드 메뉴가 있어야 한다.

## 5. 기술 결정 (제 판단, 사용자 확정 아님)

- **형태**: 일반 TUI. ghostty와 herdr 분할 창을 포함한 대부분의 터미널에서 동일 바이너리가 동작한다. herdr/ghostty 전용 방식은 이식성만 잃고 쉬워지는 것이 없어 택하지 않는다.
- **언어/프레임워크**: Rust + ratatui + crossterm. 근거: 단일 바이너리, 빠른 시작과 큰 히스토리에서의 성능, 풍부한 레이아웃/색 표현. 차선책은 Go + Bubble Tea.
- **git 연동**: `git` CLI 호출(libgit2 미사용). 실제 git과 동작이 일치하고 의존성이 적다.
- **변경 감지**: 파일 시스템 감시(`notify` 등)로 `.git` ref와 작업 트리 변화를 감지한다.
- **배포**: Homebrew 탭/GitHub Releases 바이너리를 우선 고려한다(상세는 빌더 재량).

## 6. 빌더 재량

- 크레이트 선택, 모듈 구조, 키 매핑, 색 테마, 레인 색 배정 알고리즘, 폭별 레이아웃 전환 기준, 캐시 구조.
- 구현 순서는 읽기 전용 뷰어(그래프+상세+diff+실시간) → Git 동작 → Manygit로 단계를 나누는 것을 권장하되 조정 가능하다.
- 테스트 방식. 원본은 임시 저장소(bare "remote" 포함)를 만들어 실제 git으로 검증했다. 같은 접근을 권장한다.

## 6.0 사용자 결정

- **충돌 처리**: merge/rebase/cherry-pick/revert가 충돌로 멈추면 git의 오류 메시지를 그대로 보여 주고 끝낸다. 진행 중 상태 표시나 continue/abort UI는 만들지 않는다(사용자가 셸에서 마무리). 따라서 git 실행은 출력을 캡처하는 방식이며, 터미널을 git에 넘기는 대화형 실행은 필요 없다.
- **Uncommitted의 reset**: tracked 파일만 `git reset --hard`로 되돌리고 untracked 파일은 건드리지 않는다. `git clean`은 제공하지 않는다. 확인 대화상자에 "untracked 파일은 유지됨"을 명시한다. Uncommitted 행의 (N)은 tracked 변경과 untracked를 합산해 표시하되 구분해서 보여 준다.

## 6.1 검토에서 나온 질문에 대한 결정 (**제 판단**, 확인 필요)

- **진입점**: `tgg [경로]`. 경로가 없으면 현재 디렉터리. 저장소(일반, 하위 디렉터리, linked worktree, bare 저장소의 worktree 포함) 안이면 그 저장소의 그래프를, 아니면 Manygit 목록을 연다. 단일 바이너리, 한 진입점이며 `git rev-parse`로 판별한다.
- **그래프 범위**: 원본을 따른다. All branches = 모든 로컬/원격 브랜치와 태그, Current = 현재 브랜치. 정렬은 토폴로지 순을 따르는 최신순. Remotes 토글은 라벨과 원격에만 도달 가능한 커밋을 함께 숨긴다. 커밋 수는 로드한 개수가 아니라 전체 개수를 보여 준다(계산이 느리면 로드한 개수로 대체). detached HEAD는 HEAD 라벨로 표시한다.
- **성능**: 레인 계산은 페이지 단위 증분 방식을 권장한다. 목표는 §7의 수치이며, 측정 기준은 캐시 없는 콜드 스타트, 최근 Apple Silicon Mac이다. 구체적 구조는 빌더 재량.
- **터미널 검증**: ghostty와 herdr 분할 창에서 직접 확인한다. 마우스나 트루컬러가 없으면 키보드 전용/256색으로 대체한다. 40~60칸은 하드 요구사항이 아니라 우선 설계 대상 폭이다.
- **클립보드**: macOS는 `pbcopy`, 그 외는 OSC 52를 쓰고 실패하면 대화상자에 값을 보여 준다.
- **원격 페이지/설정**: 원격 URL을 https로 변환해 `open`(macOS)/`xdg-open`으로 연다(GitHub/GitLab 등 일반 형식). 설정은 `~/.config/terminal-git-graph/config.toml` 하나이며 Manygit 깊이, 태그 표시, 색 테마를 담는다. 설정 UI는 없다.

## 7. 성공 기준

- 수만 커밋 저장소에서 첫 화면이 체감상 즉시 뜨고(대략 1초 이내), 스크롤이 끊기지 않는다.
- §4의 모든 기능이 ghostty와 herdr 분할 창에서 동작한다.
- 상태 변경 동작은 항상 확인을 거치고, git 오류가 그대로 전달된다.
- 의존성 라이선스 검사를 통과한다.
